# UI/UX Analyzer Pro

استوديو احترافي باللغة العربية لتحليل وفحص وتحرير صفحات الويب وقوالب بلوجر **بشكل حي**، مع تحريك هندسي دقيق للعناصر، وتعديل برمجي مباشر بالمقارنة مع الكود القديم، وتفكيك العناصر المركبة، وكل ذلك **بمزامنة فورية مع الكود المصدر** في وضعي `HTML/CSS/JS` وقوالب بلوجر `XML`.

## المزايا

### 1. أوضاع تحرير ثلاث متكاملة

- **كود عادي (HTML / CSS / JS)**: محرر بثلاثة تبويبات مع تلوين برمجي، وأرقام أسطر، وبحث سريع (`Ctrl + F`)، وتنسيق تلقائي للكود، وعرض حية تلقائي.
- **قالب بلوجر (XML)**: محرك ترجمة عالي الدقة لقوالب بلوجر يدعم `<b:skin>` و`CDATA` و`<b:includable>` و`<b:if>/<b:elseif>/<b:else/>` و`<b:loop>` و`<data:.../>` و`expr:href`، مع محاكاة صفحات **الرئيسية / المقال / الأرشيف**.
- **وضع التعديل الذكي**: عرض التطبيق أو المدونة بملء الشاشة مع قائمة منسدلة احترافية عند النقر بزر الفأرة الأيمن على أي عنصر.

### 2. تحريك العناصر هندسياً

- سحب حر للعنصر داخل الصفحة مع إطار تحكم هندسي (CAD) يعرض الإحداثيات `X / Y` لحظياً.
- مساطر قياس مسافات بالبكسل بين العنصر وحاويته، وخطوط محاذاة مغناطيسية للوسط الأفقي والرأسي.
- شبكة هندسية (`1px / 8px / 16px`)، وتحريك بالأسهم (`Shift = 10px`)، وإدخال إحداثيات رقمي.
- نقل ترتيبي هيكلي داخل الصفحة (تقديم / تأخير) في الوضعين `HTML` و`XML`.
- خيار **فصل هذا العنصر فقط** تلقائياً عندما يشترك مع عناصر شقيقة في نفس الكلاس.

### 3. التعديل البرمجي المباشر

- عرض **الكود القديم (الأصلي)** بجانب **محرر الكود الجديد** مع عدّاد الأسطر المعدّلة.
- تبويبان مستقلان: هيكل العنصر (`HTML/XML`) وقواعد تنسيقه (`CSS`).
- **معاينة التعديل بالصفحة** قبل الحفظ، و**إرجاع للكود القديم** بضغطة واحدة، و**حفظ واعتماد** بالمزامنة الكاملة مع الكود المصدر.

### 4. التعديل المتقدم للخصائص

- تفكيك العناصر المركبة إلى أجزائها (نصوص مدمجة، عناوين، أيقونات، أزرار وروابط فرعية) مع تعديل كل جزء منفرداً دون المساس بالأيقونات.
- **فصل التنسيق** بمعرّف مستقل للعناصر المشتركة في الكلاس.
- **فك تجميع الحاوية** مع الإبقاء على العناصر الداخلية مستقلة.
- **عزل بصري للمكوّن** (Spotlight) وتفعيل **تفكيك بصري** للطبقات المتداخلة.
- **استخراج كود المكوّن المستقل** (`HTML + CSS`) جاهزاً للنسخ.

### 5. خريطة الروابط والأزرار

- كشف تلقائي لجميع الروابط والأزرار والمشغّلات التفاعلية في الصفحة وتصنيفها: **خارجية / مرساة داخلية (`#id`) / متحكم بمكوّن / بلوجر ديناميكي / حدث JavaScript**.
- خطوط ربط بصرية (SVG) تربط كل زر بالمكوّن الذي يتحكم به داخل الصفحة.
- تعديل `href` و`onclick` و`_blank` مباشرة، وإلحاق رابط جديد بأي عنصر غير مرتبط، مع **فتح آمن للروابط الخارجية** في تبويب علوي نظيف (معفي من قيود COOP) ونسخ تلقائي كحل احتياطي.

### 6. فحص UX وإمكانية الوصول

- مؤشر جودة شامل مع فحوصات: **التباين اللوني (WCAG AA/AAA)**، مساحة اللمس والأزرار، صغر الخطوط، الروابط المكسورة، الصور بدون `alt`، والتجاوز الأفقي.
- **إصلاح تلقائي بضغطة واحدة** لكل ملاحظة مع مزامنتها في الكود المصدر.

### 7. معاينة واقعية

- أبعاد سطح مكتب حقيقية (`1366px`) بملاءمة ذكية، وتابلت (`768px`) وجوال (`390×844px`) بإطار جهاز.
- كشف تلقائي لاتجاه الصفحة (`RTL / LTR`) مع إمكانية فرضه، والحفاظ الكامل على خطوط وCDNs الصفحات المستوردة.
- سجل `Console` حي (رسائل، تحذيرات، أخطاء، تنبيهات) مع تصفية.
- سجل **تراجع / إعادة (`Undo / Redo`)** يغطي كل العمليات المرئية والبرمجية.

## النشر على Vercel (الخيار الموصى به)

المشروع مُهيأ بالكامل للنشر على **Vercel** من أول دفعه — ملف `vercel.json` موجود ويتولى كل شيء:

- اكتشاف إطار العمل (`Vite`) وأمر البناء (`npm run build`) ومجلد الإخراج (`dist`).
- إعادة كتابة SPA (أي مسار يقدّم `index.html`).
- رؤوس أمان (`X-Content-Type-Options`، `Referrer-Policy`، `X-Frame-Options`، `Permissions-Policy`).
- سياسة تخزين مؤقت مُحكمة: تحديث فوري لصفحة التطبيق + تخزين دائم (`immutable`) للأصول المرقّمة.

### الطريقة الأولى: من لوحة Vercel (الأسهل)

1. ارفع المشروع إلى مستودع GitHub (انظر أوامر الرفع أدناه).
2. من [vercel.com](https://vercel.com): **Add New → Project** → اختر المستودع.
3. اترك الإعدادات كما هي (يُكتشف Vite تلقائياً) ثم **Deploy**.
4. يصلك رابط جاهز: `https://<project>.vercel.app` — ويُعاد النشر تلقائياً مع كل `git push` إلى `main`.

### الطريقة الثانية: عبر سطر الأوامر (Vercel CLI)

```bash
npm i -g vercel          # مرة واحدة فقط
vercel                   # معاينة مؤقتة فورية (Preview URL)
vercel --prod            # نشر الإنتاجي
```

> لا حاجة لأي إعداد مسارات (Base Path) لأن الناتج ملف واحد مكتفٍ ذاتياً يعمل من أي مسار.

## البديل: النشر على GitHub Pages

يشمل المشروع أيضاً ملف سير عمل جاهزاً: `.github/workflows/pages.yml` (فحص TypeScript + بناء + نشر). لتفعيل النشر على Pages:

1. من المستودع: `Settings` → `Pages` → `Source` → اختر **`GitHub Actions`**.
2. أي `git push` قادم إلى `main` سيُبنى ويُنشر تلقائياً على:

```
https://<your-username>.github.io/<repo-name>/
```

> إذا اخترت Vercel بدلاً من Pages لا تحتاج هذه الخطوة — وسير العمل سيكمل بنجاح في كل الأحوال.
